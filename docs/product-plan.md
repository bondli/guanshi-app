# 管事 GuanShi — 产品方案

> 一个住在云端的 AI 管事助理：帮你发现、记住、盯住生活里那些"该做但容易忘"的事，
> 每天早上告诉你今天要做什么，晚上陪你复盘做完了没有。

版本 v4.0 | 2026-11-25

---

## 一、问题定义

### 1.1 用户是谁

**"承诺型遗忘者"**：不是不想做，也不是不会做，而是——

- 对别人的请求习惯性说"好"，转身就被下一件事覆盖
- 对周期性事务（订票、缴费）总是拖到临期才想起
- 对"未来某天"的时间缺乏空间感，觉得还很远
- 结果：事情在心里记着，但从来不会在正确的时间出现在眼前

**人群画像**：25–45 岁、有工作、有家庭、有孩子、日常使用微信/电商/高铁通勤，每天被大量信息流过但没有第二个大脑接住。

### 1.2 七类典型遗忘

| # | 场景 | 现实表现 | 遗忘代价 |
|---|---|---|---|
| 1 | 聊天中的口头约定 | 微信里答应"下周三一起吃饭"，然后忘了 | 失信、关系受损 |
| 2 | 周期性通勤订票 | 每周一余姚北→杭州、周五返回，总忘记买票 | 无票、改签、迟到 |
| 3 | 快递取件 | 短信通知了，漏看，包裹在驿站吃灰 | 滞留、退回、生鲜变质 |
| 4 | 家人生日 | 记不清谁哪天生日，错过才想起来 | 情感损失 |
| 5 | 孩子学校事项 | 孩子说了要带东西，口头答应后忘了 | 被孩子责怪、孩子受委屈 |
| 6 | 节日送礼 | 母亲节到了才反应，来不及准备 | 临时凑合、心意打折 |
| 7 | 收藏夹里的好东西 | 抖音/微信收藏了，从此再没打开 | 沉没成本、错失价值 |

### 1.3 现有方案为什么不行

| 现有方案 | 缺口 |
|---|---|
| 系统日历 / 闹钟 | 要手动创建，创建成本就是门槛；只管"提醒"，不管"发现" |
| 待办 App（滴答清单等） | 功能强大但依然是"手动录入"，记不住的人不会去记 |
| 厂商语音助手 | 一问一答即走，没有持续跟进，不会主动回头找你 |
| 电商/快递 App 通知 | 单点提醒，不进入统一的"今天要做什么"视图，容易被淹没 |
| 微信收藏 / 备忘录 | 只存不管，没有回顾机制 |

**核心矛盾**：所有工具都假设"用户会主动记录"，而目标用户的问题恰恰是"不会主动记录"。

## 二、产品定位

### 2.1 一句话

**管事 = 一个不需要你主动记录、会主动找你的生活事务助理，也是一个能陪你聊两句的生活参谋。**

你只需要顺手把信号交给它（截图、说一句话、开着短信权限），剩下的发现、判断时机、提醒、跟进、复盘，它全包。

它不要求你一开始就说清楚要干什么。你可以先问"母亲节适合送什么"，聊到最后补一句"那提醒我明天去淘宝看看"——它接得住，也记得住。

### 2.2 核心概念：Duty（待办义务）

产品里所有东西统一叫 **Duty**——不是"任务"，而是"一件有时限、有代价、该被推进的事"。

```
发现 → 确认 → 提醒 → 推进 → 完成 / 过期 / 放弃
```

每个 Duty 都带三个要素：**是什么**（内容）、**什么时候**（截止/最佳行动窗口）、**凭什么**（来源可追溯：哪条短信、哪张截图、哪句话）。

### 2.3 对话：既能闲聊，也能落地

产品的助手页不是"命令输入框"，而是一段可以随便开始的对话。**用户往往不是一开始就知道自己要什么，意图是聊出来的。**

```
用户：母亲节适合送什么？
管事：看你妈妈的性格。实用一点可以送按摩仪或护颈枕，
      想要仪式感就鲜花 + 一顿饭。她最近提过什么想要的东西吗？
用户：她老说肩膀疼
管事：那按摩仪是个好选择，300–500 元就能买到不错的。
用户：行，那提醒我明天去淘宝上看看
管事：记下了。明天上午 10 点提醒你去淘宝挑按摩仪。
      [ 改时间 ]  [ 不用了 ]
```

这段对话里有三个产品判断：

| 判断 | 说明 |
|---|---|
| **闲聊不设防** | 不需要先选"新建待办"，直接问就行。降低开口门槛 |
| **理解要落到执行** | "提醒我明天去淘宝看看"是模糊指令，系统要能补全成可执行 Duty（明天 + 淘宝 + 按摩仪 + 上午 10 点） |
| **承接上下文** | "那"指代的是按摩仪，不是鲜花。上一轮聊的内容必须进入下一轮的记忆 |

**这解决了什么**：多数待办工具要求用户"先想清楚、再结构化录入"，而真实场景里，人是在聊的过程中才想清楚要做什么的。**对话是漏斗的上游，Duty 是漏斗的下游。**

**边界**：话题收在生活事务上（送礼、家务、孩子、出行、健康），不做"问我任何事"的通用问答；每次对话的落点都是"要不要我帮你盯着"。

### 2.4 五条产品原则

| 原则 | 含义 | 反面案例 |
|---|---|---|
| **主动但不打扰** | 该说的时候说，不该说的时候闭嘴。提醒频率可调，可学习 | 每 10 分钟弹一次 |
| **AI 生成，人来确认** | 所有自动识别的结果都要用户一眼可确认/修改/驳回 | 猜错了还硬推 |
| **确认即止** | 用户标记完成后，永不重复提醒同一件事 | 做完还催 |
| **可追溯** | 每条 Duty 都能看到来源和识别依据 | 凭空冒出一条待办 |
| **对话即入口** | 用户可以闲聊，最后一句才是"帮我记下"，系统要接得住 | 只认结构化指令，聊完就忘 |

### 2.5 不做什么（边界）

- ❌ 不做通用问答机器人（不做"问我任何事"；可以闲聊，但话题围绕生活事务，且每次对话都能落到"要不要帮你盯着"）
- ❌ 不做团队协作/项目管理（不做多人任务分配）
- ❌ 不做记账、笔记、日历全家桶
- ❌ 不替用户自动执行有副作用的操作（如自动下单、自动付款）——只推到"你该动手了"
- ❌ 不做 iOS（先专注 Android 的采集能力优势）

## 三、使用场景

### 3.1 七类场景的产品行为

**场景 1｜聊天约定**
- 触发：你在微信聊完，截图分享给管事
- 产品：识别出"下周三和张三吃晚饭"→ 弹确认卡 → 你点确认 → 建 Duty
- 之后：前一天提醒一次，当天提醒一次，附一条预制话术"明天晚饭老地方？"
- 用户感受："我只截了张图，它记住了。"

**场景 2｜周期性通勤订票**
- 触发：一次性配置"每周一 余姚北→杭州，每周五 杭州→余姚北"
- 产品：自动生成循环 Duty
- 之后：周三推"周五的票该订了"→ 周四未订升级→ 周五当天仍未订，紧急提醒 + 建议车次
- 用户感受："不用我记，它比我记事。"

**场景 3｜快递取件**
- 触发：收到快递短信，自动识别
- 产品：提取取件码 + 站点 → 生成 Duty（标记为 AI 识别，可一键确认或忽略）
- 之后：当天傍晚提醒一次，次日再提醒一次；超过 48 小时未取加强提醒
- 用户感受："包裹不再吃灰。"

**场景 4｜家人生日**
- 触发：一次性录入家人和生日
- 产品：每年自动循环
- 之后：提前 7 天提醒"下周三妈妈生日"，提前 1 天再提醒
- 用户感受："再也不会当场尴尬。"

**场景 5｜孩子学校事项**
- 触发：孩子说完，你在 App 里说一句话或输入一句
- 产品：识别成"明天要带 3 支铅笔和跳绳"→ 建 Duty，挂在"孩子/学校"分类下
- 之后：当晚提醒准备，次日早上再提醒一次
- 用户感受："孩子说一遍就够。"

**场景 6｜节日送礼**
- 触发：内置节日表（母亲节、父亲节、教师节、中秋…）
- 产品：提前 14 天创建 Duty + 给出准备建议（买花/买礼/订蛋糕）
- 之后：提前 14 天提醒"该准备了"，提前 3 天再提醒
- 用户感受："这次不是临时抱佛脚。"

**场景 7｜收藏内容回顾**
- 触发：在微信、抖音、小红书里看到好东西，点「分享」→ 选择管事
- 产品：链接 / 图片 / 文字直接收进「收藏」，静默入库，不打扰
- 之后：每周日晚批量回顾一条推送："这周你收藏了 5 条，扫一眼？"
- 用户感受："收藏夹活了。"

### 3.2 三个核心仪式（产品的骨架）

这是管事区别于普通待办 App 的关键——**它有节奏**。

三条仪式共用一条对话线索：晨报和复盘本身就是助手发出的两条消息，点击推送会回到助手里的那一句，而不是另开一个清单页。

#### 仪式一：每日晨报（早上，时间可配，默认 07:30）

```
推送标题：今天 3 件事
推送内容：
  · 09:00 前  带跳绳和彩笔去学校
  · 18:00 前  取快递（菜鸟驿站余姚店，码 12345）
  · 今晚      给妈妈打个电话（生日前 3 天）

  通知上直接可做：
  [ 全部已读 ]  [ 打开管事 ]
```

- **作用**：把散落的 Duty 收拢成"今天要做什么"的一份清单，一次推送解决
- **关键**：用户可以在通知上直接标记完成，也可以打开 App 逐条确认
- **价值**：这是用户每天唯一必看的一条推送，建立习惯锚点

#### 仪式二：晚间复盘（晚上，时间可配，默认 21:00）

```
推送标题：今天完成 2/3
推送内容：
  ✅ 学校物品已准备
  ✅ 快递已取
  ⬜ 给妈妈打电话  →  [ 明天提醒 ]  [ 现在就打 ]

  本周完成率 78%，比上周高 12%
```

- **作用**：闭环。让"完成"被看见，让"没完成"有去处（顺延到明天，而不是消失）
- **价值**：完成感 = 留存。没有复盘的待办 App，用户三天就弃用

#### 仪式三：助手对话（随时）

```
入口：底部 Tab「助手」
形态：像微信一样的对话界面
输入：文字 / 截图 / 语音
```

用户可以说：
- "下周三提醒我交房租" → 直接建 Duty
- "我妈生日是 4 月 15 日" → 写入长期记忆
- "我每周一都要去杭州上班" → 建循环 Duty
- （发一张聊天截图）→ 识别约定
- "母亲节送什么好？" → 先闲聊给建议，聊完再落地成 Duty
- "我最近老忘事，帮我看看这周漏了什么" → 回顾与分析

**闲聊落地的三段式**（产品上必须显式）：
1. **听懂上下文**：知道"那"指的是上一轮的按摩仪
2. **补全模糊指令**："明天去淘宝看看" → 明天上午 + 淘宝 + 按摩仪
3. **可改可撤**：生成时给出具体时间，并附"改时间 / 不用了"

**价值**：这是用户主动"喂"信息的最低摩擦通道，也是产品的记忆入口。聊天不是装饰，它是把"想法"变成"待办"的转化器。

### 3.3 收藏：把看到的好东西收进来

第 7 类场景值得单独说，因为它的入口不在 App 里，而在**别的 App 的分享面板**。

```
在微信 / 抖音 / 小红书 / 浏览器里
  ↓  点「分享」
选择「管事」
  ↓
链接、图片、一段文字都能收进来，不需要复制粘贴
```

**三种收藏形态**

| 类型 | 来源示例 | 收到后 |
|---|---|---|
| 链接 | 抖音视频、公众号文章、小红书笔记 | 抓标题、封面、来源，存成卡片 |
| 图片 | 截图、菜谱、海报 | 存原图，可加备注 |
| 文字 | 一段话、一串地址 | 直接存文本，可一键转成待办 |

**收藏不是终点，回顾才是**

- 收藏默认**静默入库**：不弹提醒、不进今日、不占待办
- 每周日 21:00 的周回顾里带一条："这周你收了 5 条，扫一眼？"
- 回顾时三选一：**留着**（进精选）/ **转成待办**（"周末做这道菜"）/ **删掉**
- 一条收藏放满 30 天没被回顾，自动归档，不再出现在周回顾里

**为什么要单独一个 Tab**

待办是"欠着的事"，收藏是"想要的东西"。混在一起，收藏会污染待办清单；单独放，才能放心地"先收着"。

**一条产品判断**：收藏的价值不在"存"，而在"回头用"。所以产品重心不是做一个更漂亮的收藏夹，而是**在周回顾里制造一次低成本的重逢**。

### 3.4 一个典型的周循环

```
周一早 07:30   晨报：3 件事（含周五订票提醒在下周三）
周一~周五      快递短信自动进来 → 傍晚提醒
周三 12:00     推送：周五回余姚北的票该订了
周五 18:00     推送：别忘了今晚的车（如果已订则不再提）
周日 21:00     周回顾：本周收藏 5 条 + 完成率 78%
```

## 四、用户动线

### 4.1 首次启动（3 分钟完成）

```
打开 App
  ↓
一句话介绍："我不会让你再忘事。先告诉我一件你总忘的事。"
  ↓
选择提醒风格（安静 / 标准 / 主动）
  ↓
创建第一个 Duty（示例引导：录入一个家人生日，或配置每周通勤）
  ↓
按需授权（每项都有"现在不要"）
  · 短信权限 —— 自动识别快递
  · 通知权限 —— 从微信/电商通知里发现事项
  · 麦克风 —— 说话建待办
  · 电池优化白名单 —— 让提醒更可靠
  ↓
完成，进入今日视图
```

**设计要点**：首启不要求注册账号（设备即身份），不要求一次性给全部权限，先让用户体验到"它记住了"的爽感，再逐步引导授权。

### 4.2 日常被动动线：通知即对话（最高频，占 80% 使用）

**一条推送 = 助手的一次发言。点击通知，落到助手，而不是清单。**

```
收到推送（晨报 / 单条提醒 / 晚报）
  ↓
通知栏可直接操作（完成 / 稍后 / 打开）
  ↓  或点击通知
打开 App → 直接进入助手 → 定位到这条消息并高亮
  ↓
消息里是一张可操作卡片：
  · 晨报 → 今日清单卡（逐条勾选 / 全部完成）
  · 单条 → 事项卡（已完成 / 明天 / 不是我的 / 看原文）
  · 复盘 → 完成度卡（未完成项一键顺延）
  ↓
可以直接在卡片上操作，也可以接着说：
  "取件码多少" / "改到明天早上" / "这件不做了"
  ↓
状态同步，后续不再重复提醒
```

**为什么落在助手，而不是今日页**

| 视图 | 回答的问题 | 局限 |
|---|---|---|
| 今日清单 | 今天一共有什么 | 不知道"刚刚发生了什么"，也不能追问 |
| 助手对话 | 刚刚发生了什么、现在要我做什么 | 需要控制噪音 |

推送是一次"事件"，清单是一次"清点"。用户点通知时的心理是"刚刚发生什么了"，所以应该落在他刚刚被通知的那句话上。

**三条约束**

1. **一条推送只对应一条消息**：同一天同一事项的多次提醒合并为一条，更新次数而不是刷屏。
2. **消息卡必须可操作**：完成、顺延、看原文都在卡上，不要求回到今日页。
3. **助手 Tab 有未读点**：有未读推送时显示小圆点，进入即清；自动消息按天分组，避免淹没用户自己的对话。

**设计要点**：能在通知栏完成的，绝不要求打开 App；需要打开的，一定落到助手的那条消息上。

### 4.3 采集动线（短信 / 通知）

```
新短信到达
  ↓
端侧识别（快递关键词命中）
  ↓
生成 Duty（状态：待确认）
  ↓
用户下次打开 App 或收到推送时看到：
  "识别到一条快递：菜鸟驿站余姚店，取件码 12345"  [ 确认 ] [ 不是我的 ] [ 忽略 ]
  ↓
确认后进入正常提醒流程
```

**设计要点**：AI 识别的结果默认"待确认"，不直接当成事实催用户。识别错了，用户点"不是我的"，系统记住并降低同类识别置信度。

### 4.4 助手对话动线

```
进入助手 Tab
  ↓
输入：文字 / 发图（截图）/ 按住说话
  ↓
助手回复（流式）：
  理解了什么 → 打算做什么 → 请你确认
  例："你和张三约了下周三（12月3日）晚饭，要我到时候提醒你吗？"
  ↓
用户：[ 好的 ] / [ 改成周四 ] / [ 不用 ]
  ↓
生成 Duty 或写入记忆，回复："记下了。周三下午 5 点提醒你。"
```

**设计要点**：助手回复必须包含三件事——**理解了什么、要做什么、请你确认**。不要只回"好的"，用户会不放心。

### 4.5 收藏动线（分享进来 → 周日回顾）

```
在微信 / 抖音 / 小红书里点「分享」
  ↓
选择「管事」（系统分享面板，第一次需要在设置里开启）
  ↓
自动识别类型：
  链接 → 抓标题、封面、来源
  图片 → 存原图
  文字 → 存文本
  ↓
静默入库，只弹一条轻提示："已收藏 · 周日回顾时会提醒你"
  ↓
周日 21:00 周回顾推送 → 点进来是收藏页
  ↓
逐条三选一：留着 / 转成待办 / 删掉
  ↓
转成待办的进入今日清单，收藏标记为已回顾
```

**设计要点**：收藏的默认动作必须是"什么都不问"。一旦要求用户选分类、打标签，收藏这个动作就死了。分类和标签都是事后回顾时才需要的东西。

### 4.6 处理"忘记"的动线（挽回机制）

```
一条 Duty 过期未完成
  ↓
不静默消失，进入"待处理"
  ↓
晚间复盘时提出：
  "给妈妈打电话这件事已经过了 3 天，还要做吗？"
  [ 明天提醒 ] [ 已完成 ] [ 放弃 ]
  ↓
用户选择 → 状态明确 → 不留悬案
```

**设计要点**：**没有"悄悄消失"的 Duty**。这是信任的底线。

## 五、功能结构（信息架构）

### 5.1 五个主 Tab

```
┌───────────────────────────────────────────────┐
│  今日    全部    助手    收藏    我的           │
└───────────────────────────────────────────────┘
```

#### Tab 1｜今日（默认首页）

- 顶部：日期 + 一句话（"今天 3 件事"）
- 主体：今日 Duty 卡片列表（按时间排序）
  - 每张卡：标题 / 时间 / 来源标记（短信·截图·语音·手动）/ 快捷操作
  - 支持左滑完成、长按改期
- 分区：**待办** / **待确认**（AI 识别的，需你点头）/ **已完成**（可折叠）
- 底部：明日预览（"明天还有 2 件"）

#### Tab 2｜全部

- 按类型筛选：快递 / 约定 / 生日 / 节日 / 习惯 / 学校 / 收藏
- 按状态筛选：进行中 / 已完成 / 已过期 / 已放弃
- 日历视图（月度，看哪天有什么）
- 搜索

#### Tab 3｜助手

- 对话流（类微信）
- **推送的落点**：点击任何推送都进入这里，并定位到对应的那条消息
- 自动消息用卡片形态（晨报清单 / 事项卡 / 复盘卡），与用户自己的对话在同一线程
- 有未读推送时 Tab 显示小圆点，进入即清
- 输入区：文字、图片、语音
- 能力入口（快捷指令）：
  - 截图识别约定
  - 说一句记件事
  - 录入家人生日
  - 配置周期习惯
  - 本周复盘
- 对话中生成 Duty 时，内嵌确认卡片（可直接操作）

#### Tab 4｜收藏

- 入口一：**别处分享进来**——微信 / 抖音 / 小红书 / 浏览器 → 分享 → 管事
- 入口二：App 内右上角「+」手动添加链接
- 顶部：本周收到 N 条 · M 条待回顾
- 引流卡：第一次进入时提示"在微信里点分享，选择管事"
- 筛选：全部 / 待回顾 / 已回顾；按来源（抖音 / 微信 / 小红书 / 网页）
- 卡片：封面缩略图 / 标题 / 来源 / 收藏时间 / 状态
- 点开详情：预览原文、备注、**转成待办**、标记已回顾、删除
- 周回顾入口：周日 21:00 推送，点进来就是这一屏

#### Tab 5｜我的

- 提醒风格（安静 / 标准 / 主动）+ 晨报晚报时间
- 数据来源管理（短信 / 通知 / 语音，逐项开关）
- 家人与关系（生日、称呼）
- 周期习惯管理（通勤、缴费等）
- 权限与保活引导
- 数据导出 / 删除

### 5.2 关键页面

| 页面 | 核心内容 |
|---|---|
| Duty 详情 | 内容、时间、来源原文、识别依据、历史提醒记录、操作（完成/改期/放弃/打电话/复制取件码） |
| 来源原文 | 短信原文 / 截图 / 语音转写，可追溯 |
| 助手对话详情 | 多轮对话 + 内嵌 Duty 卡片 + 记忆写入提示 |
| 收藏详情 | 预览原文、来源链接、备注、转成待办、标记已回顾、删除 |
| 周回顾 | 完成率趋势、常忘类型、漏掉的事 |

## 六、价值与收益

### 6.1 用户价值

| 价值 | 具体体现 |
|---|---|
| **省心** | 不用记，不用建待办，不用管理工具 |
| **不失信** | 承诺过的事有人帮你盯着 |
| **省钱省事** | 快递不滞留、票不涨价、礼物不临时买 |
| **情感价值** | 生日、节日、孩子的事不再错过 |
| **完成感** | 每日复盘带来正反馈，而不是无尽的待办焦虑 |

### 6.2 商业价值

| 层级 | 定价 | 内容 |
|---|---|---|
| 免费 | 0 | 手动待办 + 每日晨报/晚报 + 最多 5 个循环 Duty |
| 高级 | ¥25–29/月 或 ¥238/年 | 短信自动识别 + 通知监听 + 无限 Duty + 助手对话 + 长期记忆 + 收藏回顾 |
| 家庭 | ¥49/月 | 高级 + 家庭共享（多人 Duty、孩子事项协同） |

**为什么能收费**：用户不是为"提醒"付费，而是为"不再因为忘记而付出代价"付费。一次错过的生日、一次没取的生鲜，价值就超过年费。

### 6.3 衡量指标

| 层级 | 指标 | 目标 |
|---|---|---|
| **北极星** | 周活跃用户的人均 Duty 完成数 | 稳态 ≥ 8 件/周 |
| 留存 | 次日 / 7 日 / 30 日留存 | 50% / 30% / 18% |
| 习惯 | 晨报打开率 / 晚报查看率 | ≥ 45% / ≥ 30% |
| 信任 | AI 识别确认率（确认 / 总识别） | ≥ 80% |
| 打扰度 | 推送点击率 / 关闭推送比例 | ≥ 12% / ≤ 5% |
| 商业 | 免费转付费率 | ≥ 4% |

## 七、竞对调研

### 7.1 直接与间接竞品

| 产品 | 定位 | 自动发现 | 主动推送 | 云端存活 | 每日仪式 | 价格 |
|---|---|---|---|---|---|---|
| **滴答清单** | 全能待办 | ❌ 手动 | ⚠️ 弱 | ⚠️ 依赖端 | ❌ | 免费/¥139年 |
| **Sunsama** | 每日计划 + 收尾仪式 | ❌ 手动 | ⚠️ 弱 | ✅ | ✅✅ 标杆 | $20/月 |
| **Claude Duet** | 云端工作流 agent | ⚠️ 连账户 | ✅ | ✅ | ❌ | 订阅制 |
| **Mem** | AI 记忆库 | ❌ | ❌ | ✅ | ❌ | $10/月 |
| **Rewind / Limitless** | 全量记录检索 | ✅ 记录 | ❌ | ✅ | ❌ | 订阅制 |
| **智记妞妞 / SmoreAI / Talkminder** | 语音建待办 | ❌ 需用户说 | ⚠️ | ⚠️ | ❌ | 免费+内购 |
| **系统日历 / 闹钟** | 基础提醒 | ❌ | ⚠️ | ✅ | ❌ | 免费 |

### 7.2 结论：市场空位

```
                    自动发现（不用手动录）
                          ▲
                          │
              管事 ◆      │
                          │
  手动录入 ◄──────────────┼──────────────► 云端执行任务
                          │
   滴答/Sunsama           │      Claude Duet
   智记/妞妞              │      Mem / Rewind
                          ▼
                    被动/半主动
```

**三方能力的交集处是空的**：
1. **自动发现**（短信/通知/截图，不用你录）
2. **主动时机判断**（不是倒计时，而是"现在说才有用"）
3. **云端常驻**（杀 App 照样提醒）

现有产品各占一角，没有产品同时做到三点，且聚焦**生活琐事**这一垂直场景。

### 7.3 可借鉴的最佳实践

| 来源 | 借鉴点 |
|---|---|
| **Sunsama** | "晨间计划 + 晚间收尾"的双仪式设计，是全行业验证过的最强留存手段 |
| **Claude Duet** | "它先来找你"的主动式交互范式；生成提醒前先准备好下一步 |
| **滴答清单** | 清单的组织方式、快捷操作、通知栏直接完成 |
| **Rewind** | 全量感知 → 结构化 → 可检索的思路，但管事只做"事务"而非"全部记忆" |

## 八、实现路径

### Phase 1｜云端骨架 + 每日仪式（4 周）

**目标**：跑通"它记住了、它会提醒、杀 App 也提醒"的最小闭环。

```
功能：
✅ 手动建 Duty（文字/语音输入）
✅ 周期 Duty（生日 / 节日 / 每周通勤）
✅ 每日晨报（通知栏可标记完成）
✅ 晚间复盘（完成度统计）
✅ 云端推送（杀 App 可达）
✅ 助手对话（文字，能建 Duty）
✅ 确认即止（完成后不再提醒）
```

**验收**：配置"每周一五通勤" → 杀掉 App → 周三仍收到订票推送。

### Phase 2｜自动发现（4 周）

```
✅ 短信识别（快递取件码 → Duty）
✅ 截图识别约定（分享截图 → 助手解析 → 确认）
✅ 待确认区（AI 识别结果需用户点头）
✅ 收藏：系统分享面板接入（微信/抖音/小红书 → 管事）
✅ 收藏页与详情（链接 / 图片 / 文字三种形态）
✅ 每周日回顾推送 + 转成待办
✅ 通知监听（微信/电商，用户授权）
```

**验收**：在微信里分享一篇文章给管事，App 里出现一张收藏卡；周日晚推送后能把它转成待办。

### Phase 3｜主动推进与学习（4 周）

```
✅ 智能提醒时机（按用户响应习惯调整）
✅ 提醒升级与降级方案（"还没订？建议 G7502"）
✅ 批量合并（多件事合成一条推送）
✅ 长期记忆（家人生日、通勤路线、常忘类型）
✅ 周回顾报告
```

**验收**：连续忽略某类提醒后，系统自动降低该类频率；连续响应后提高。

### Phase 4｜打磨与扩展

```
桌面小组件 / 家庭共享 / 数据导出 / 更多场景模板
```

## 九、关键假设与验证

| 假设 | 风险 | 验证方式 |
|---|---|---|
| 用户愿意为了"自动发现"开短信权限 | 高 | 首启引导转化率；低于 40% 则改为"手动分享短信"的替代路径 |
| 每天一条晨报不会被视为打扰 | 中 | 晨报打开率 < 30% 则改为按需触发 |
| AI 识别准确率足够（≥80% 确认率） | 中 | 上线后统计各场景确认率，低准确率场景退回纯手动 |
| 用户会为这个付费 | 中 | Phase 1 后做 20 人访谈 + 预付意向测试 |
| 晚间复盘能带来留存 | 中 | A/B：有复盘 vs 无复盘的 7 日留存对比 |
