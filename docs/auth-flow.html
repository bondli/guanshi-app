Guanshi · Auth

userId 从哪来，请求怎么被认出来

这版没有账号密码，也没有第三方登录。App 第一次启动时在本机生成一个 deviceId，拿去换一个云端 userId， 之后每个请求都用它当 Bearer token。服务端只认这一个值，拿到就直接挂到 req.userId。

几个关键点

deviceId 是客户端自己造的，服务端不校验它是否合法，只把它当唯一索引。
token 直接等于 user.id，没有 JWT 签名、没有过期时间——这是单机 MVP 的简化， 换设备就等于换用户，重装 App 会生成新的 deviceId 和新用户。
收到 401 时客户端会自动重新 login 一次再把请求重放，所以 token 是"可自愈"的。

要上生产得补什么

1. token 换成短期 JWT + refresh token，服务端存签名密钥；
2. deviceId 加设备指纹校验，防止被猜；
3. 加 /auth/logout 与多设备管理；
4. 全链路 HTTPS，敏感接口再加限流。
这些改动都集中在 auth 中间件与 login 路由，业务代码不用动。

目前所有接口都以这条链路鉴权，包括 /chat、/duties、/collections、/events 与 /ocr。
